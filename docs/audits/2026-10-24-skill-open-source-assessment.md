# SKILL.md 内部开源评估

> **历史文档（2026-10-24，一次性评估）** — 本文的结论已落地：三项修正（含一件安全问题）
> 在 1.4.6.0 完成，SKILL.md 已拆为「随包分发的执行手册」并修掉 4 处文档错误。
> 保留原因是判断口径仍有参考价值；**不要按本文描述去操作当前的 SKILL.md**。

## 结论

**可以发布，但不能按现状原样发布。** 需要先做三件修正，其中一件是安全性质的。

分三种口径：

| 口径 | 结论 | 阻塞项 |
|------|------|--------|
| 作为「公司内部开源项目」的一部分（仓库本身已公开、MIT） | **可以直接发布** | 无（已是公开仓库） |
| 作为「可复用的 agent skill」对外分发 | **修正后可发布** | 见下方 P0 |
| 作为「内部标杆/教学样本」 | **推荐，价值很高** | 无阻塞 |

## 这个 skill 的真实价值（为什么值得发）

它不是「又一个清理脚本」，它的价值在**流程契约**这一层，而这恰好是内部开源最缺的东西：

1. **显式的确认闸门（3 道 Safety Gates）** —— 每次不可逆操作前必须停下等人。
   这不是礼貌，是设计：第 3 道闸门强制 DryRun 先行，把「预览」和「执行」拆成两次人类确认。
2. **`Danger` 项只展示不可选** —— 把「agent 判断力」从安全边界里移出去，
   改成数据结构上的硬约束。这条比任何提示词都可靠。
3. **诚实产物**：`renamed:~x.deleted` 不被记成删除成功（REQ-002）、
   回滚未完成时不写 `completed_at`、退出码 10–15 编码「部分失败 + 回滚状态」。
   大部分内部脚本在这里会说「完成」。
4. **「用户永不需要知道」清单** —— 明确列出不该暴露给用户的实现细节
   （`-NonInteractive`、`Mode A/B/C/D`、JSON 文件名）。这是 agent UX 的成熟度标志。

这三条（闸门、不可选、诚实退出码）可以直接被别的内部 skill 抄走，**这是发布的最大理由**。

## P0：发布前必须修（安全相关）

### 1. SKILL.md 完全没提它现在是一个「本地 HTTP 服务 + 管理员权限」的形态

`ui/server/` 会拉起**管理员权限的破坏性 PowerShell**。代码里对此很清醒：

```
ui/server/index.cjs:22:  // Bind loopback ONLY: this server spawns admin-privileged, destructive
ui/server/security.cjs:3: // that spawns admin-privileged PowerShell.
```

但 `SKILL.md` 里 `server`/`http`/`localhost` 出现 **0 次**。

内部开源意味着**别人会照着你写的说明书跑**。一份声称「agent 驱动、powershell -File」的
文档，配上一个会开本地端口、以管理员身份执行删除的实现——这个落差在内部推广时
会直接变成安全事故。**要么在 SKILL.md 里写清 UI 通道的存在与风险，要么在分发时明确
只发 PowerShell 管线、不含 `ui/`。**

### 2. 权限要求只是「提了一句」，没有前置检查说明

现在只写 `Requires Administrator privileges`。但实际行为是：
写入型脚本（`clean-residuals.ps1` 等）非管理员时**直接退出码 2**，
只读扫描脚本仅告警。应该写明「先跑扫描（不需要管理员）看结果，确认后**再**提权执行」——
否则用户会在第一步就撞墙，或者更糟：一直用管理员身份跑不必要的扫描。

### 3. `renamed:~x.deleted` 的语义没写 —— 这是最容易被误传的一条

`Remove-ItemRobust` 的 tier-4 会把被占用文件**改名**而非删除，内容仍在磁盘上。
代码严格区分了「删除成功」与「已改名待删除」（REQ-002），
但 SKILL.md 里只有一个示例报出了 `~mdnsNSP.dll.deleted`，**没有解释这不是删除**。

别人读到会以为「清理完成」，实际磁盘上还留着东西。必须写明。

## P1：发布前建议修（准确的诚实性问题）

### 4. 退出码表过时

SKILL.md 写的是 `0/1/2/3`。实际还有 **自动回滚扩展码 10–15**，
且优先级是 `14 > 15 > 0 > 13 > 12 > 1 > 11 > 10`。
一个 agent 读到退出码 11 会按「general error」处理，而它真实含义是
「部分失败且回滚未完全成功」——两者的用户指引完全不同。

### 5. `rollback.ps1` 的能力被低估

SKILL.md 只说它「打印可用还原点」。实际支持 `-Auto`（按消费协议自动回滚）、
`-AcknowledgeConflicts`（人工确认冲突项）。自动回滚是这个项目最独特的安全机制，
只在文档里被描述成「列个表」，等于把最强的卖点藏了。

### 6. 未提及 `-NoAutoRollback` 与所需的人工确认

`-NoAutoRollback` 是显式放弃保护，`-AcknowledgeConflicts` 是人工出口。
这两个开关应该出现在「安全闸门」章节，而不是只存在于参数表里。

## P2：发布时值得补的内容（提升复用价值）

7. **把「流程契约」抽成可复用模板**：现在它和这个项目绑死。真正可复用的是那三段结构
   （扫描→逐项确认→DryRun→执行→回滚指引），把它写成独立的一页设计说明，
   别的内部 skill 才抄得动。
8. **标注「它验证过什么」**：784 用例双引擎、PSSA 0 findings、84% 覆盖率、
   Gate 3/6/10/11 真跑。这些不是自夸，是让内部同事判断「能不能用」的依据——
   内部项目最缺的就是这类可核对的质量证据。
9. **写清已知限制**：`confirm-cleanup.ps1` 的 TUI 在部分终端会闪退；
   `wrc-drill`（会创建真实系统对象的演练脚本）已移出跟踪；
   `clean-residuals.ps1` 的 HKLM/PATH 分支需管理员环境集成测试。

## 建议的发布方式

**分两个包，而不是一个：**

| 包 | 内容 | 受众 |
|----|------|------|
| `skill/` | `SKILL.md` + `references/scripts/`（纯 PowerShell 管线） | 想直接用的同事 |
| `docs/agent-workflow-pattern.md` | 三道闸门 + Danger 不可选 + 诚实退出码的**抽象设计说明** | 想抄模式的团队 |
| **不含** | `ui/server/`（管理员权限 + 本地端口），单独说明或另包 | 需明确风险认知 |

理由：`SKILL.md` 现在描述的是纯 CLI 管线，而 `ui/server/` 是另一个安全面。
把两者混在一个「skill」里发布，会让只想用脚本的人无意中引入一个本地监听服务。

## 一句话

**项目带的 skill 值不值得发**：值得——它的「三道确认闸门 + Danger 硬不可选 +
诚实退出码」是可复用的高质量模式，比市面上大多数内部 skill 认真得多。

**能不能原样发**：不能。`SKILL.md` 停留在 2026-09-08，
已经落后于代码一个安全等级（UI 管理员服务）、一整套回滚语义（10–15）、
和两个关键参数。**先补齐 P0 三条再发**，否则内部扩散时问题会被放大。
